🚀 Adding a Real Restaurant — Onboarding Flow
Self-serve flow: 15 minutes from sign-up to first test call
Account Creation
Restaurant owner signs up with email. Supabase Auth handles verification. Select plan (Starter/Pro/Enterprise). Restaurant name, ABN, and cuisine type collected.
Supabase Auth Stripe Customer created Restaurant record in DB
Business Profile Setup
Operating hours (per day, holiday hours), address (for delivery radius), pickup/delivery options, minimum order value, special instructions (e.g. "ask for table number for dine-in"). This feeds the LLM system prompt directly.
Saved to restaurants table Auto-generates AI greeting script
Menu Upload
Three paths: (a) CSV upload with item, description, price, category, allergens columns; (b) PDF menu — AI extracts items automatically; (c) Manual entry via menu builder UI. All items embedded via OpenAI text-embedding-3-small → stored in pgvector for RAG. Custom modifiers added (sizes, extras, substitutions).
CSV / PDF / Manual pgvector embeddings Modifier groups Allergen flags
Phone Number Provisioning
Telnyx API automatically provisions an Australian local number (02, 03, 07, 08 area code) for the restaurant. The restaurant forwards their existing number to this TalkByte number, or optionally ports it. Number linked to their LiveKit routing rule in our system.
Telnyx Numbers API Auto-provisioned in <30s Call forwarding instructions shown
AI Voice Configuration
Restaurant names their AI (e.g. "Aria", "Bella"). Select voice accent (Australian female/male, various ElevenLabs voices). Customise greeting script with preview. Set escalation threshold (e.g. "after 2 failed understand attempts, transfer to staff mobile"). Configure fallback human phone number.
ElevenLabs voice selection Greeting preview playback Escalation rules
Payment Integration
Connect Stripe account (Stripe Connect onboarding — takes 3 minutes). TalkByte generates Stripe Payment Links per order and sends via SMS. Set payment expiry (default: 15 minutes). Restaurant chooses: Stripe direct, or "pay on pickup" option (skip payment link for certain order types).
Stripe Connect OAuth Payment Link config SMS template preview
POS Integration (Optional)
Connect Square, Lightspeed, or Kounta via API key. TalkByte pushes confirmed+paid orders directly to POS. If POS is offline or disconnected, system falls back to: (1) email order to restaurant, (2) SMS order summary to staff phone. Dashboard shows POS sync status per order.
Square API key Lightspeed OAuth Email fallback always active
Test Call
Dashboard shows a "Call the test number" button. Restaurant owner calls their provisioned TalkByte number. AI answers, they place a test order. System shows real-time transcript in dashboard. After call: full transcript, order summary, and simulated payment link shown. Owner approves and clicks "Go Live".
Real call, sandbox mode Live transcript in dashboard No real payment charged
Go Live ✅
System switches from sandbox to production. First real customer call accepted. Dashboard shows live status. Restaurant receives onboarding email with: their number, how to set up call forwarding, dashboard link, and support contact. 24-hour monitoring period with alert on first successful order.
Production mode enabled Call forwarding guide sent Slack alert on first order

⚠️ Risk Register
Known risks with mitigation strategies built into the architecture
🔴 Telephony cost vs BRD target
Twilio AU mobile = $0.050/min; exceeds BRD Phase 1 all-in target of $0.04/min before any other cost.
✅ Mitigation: Use Telnyx (own IP network, ~$0.018/min AU mobile). Switch to SIP trunking (Telnyx, Teler) in Phase 2 for <$0.012/min.
🔴 AI hallucination on menu items
LLM invents items not on the menu, leading to unfulfillable orders and customer complaints.
✅ Mitigation: Strict system prompt ("only offer items in the provided menu context"). pgvector RAG limits context to real items. Confidence threshold triggers clarification.
🔴 POS sync failure on high-value orders
Customer pays, but order never reaches kitchen. High-severity incident — refund required, reputation damage.
✅ Mitigation: Always have email + SMS fallback. Celery retries with exponential backoff. Restaurant dashboard shows real-time POS sync status. Alerts on failure.
🔴 OpenAI API dependency
If OpenAI has an outage, voice ordering stops across all restaurants.
✅ Mitigation: Circuit breaker pattern. Fallback to Gemini 2.5 Flash or Claude Haiku on repeated failures. Phase 2: self-hosted Llama 3.1 removes dependency entirely.
🟡 STT accent & dialect accuracy
Heavy AU regional accents, non-native English speakers, fast speech patterns reduce transcription accuracy.
✅ Mitigation: Deepgram Flux fine-tuned on AU English. Collect rejected transcript samples for ongoing fine-tuning. Low-confidence triggers repeat-request prompts.
🟡 Customer adoption friction
Customers accustomed to human staff may hang up or distrust AI. Acceptance varies by demographic.
✅ Mitigation: Easy "press 0 for staff" escape hatch. Transparent AI disclosure. Measure and track abandonment rate. Offer hybrid model (AI + human handoff).
🟡 Restaurant churn if ordering rate is low
If TalkByte doesn't improve restaurant revenue or reduce workload, they cancel.
✅ Mitigation: Track order completion rate daily. Provide ROI dashboard showing calls handled, staff time saved. Target restaurants with high phone order volume.
🟡 ACMA / Do Not Call compliance
Australian Communications and Media Authority rules on automated calling and AI disclosure.
✅ Mitigation: TalkByte receives calls (inbound only in Phase 1 — no outbound calling). Teler handles ACMA compliance for AU carrier. Legal review of AI disclosure wording in greeting.
🟢 Coqui XTTS licensing (resolved)
Previously planned TTS — company closed Jan 2024, CPML 1.0.0 prohibits commercial SaaS use.
✅ RESOLVED in SRS v2.2: Replaced with Fish Speech (Apache 2.0) for Phase 2 and Piper TTS (MIT) as alternative.
🟢 Competitive response from Uber Eats / DoorDash
Large platforms adding AI phone ordering as a feature for their restaurant partners.
✅ Mitigation: 18-month window before major platforms can ship. Build network effects (restaurant data, order history, fine-tuned models). White-label for chains is moat.

🏰 Competitive Moat — 5-Year Sustainability
What makes TalkByte hard to replicate at scale
🧠
Order Dataset Moat
Every call generates training data. At 50K restaurants × 100 calls/week = 260M order transcripts/year. Fine-tuned models on this dataset dramatically outperform generic LLMs at menu-specific ordering tasks. Impossible to replicate without the data.
🔗
POS Integration Network
Each POS integration (Square, Lightspeed, Kounta, Revel, Oracle Simphony) takes 4–8 weeks to build and certify. At 10+ integrations, TalkByte becomes the default middleware layer between AI ordering and restaurant operations. High switching cost for restaurants.
🎙️
Restaurant Voice Profiles
Stored call history, customer preferences, repeat order patterns, menu-specific STT fine-tuning per restaurant. A new competitor starts from zero — TalkByte's voice personas for each restaurant represent years of accumulated interaction data.
⚙️
Self-Hosted AI Infrastructure (Phase 2)
Moving STT (Whisper), TTS (Fish Speech), and LLM (Llama fine-tuned) off vendor APIs eliminates 65% of variable cost at scale. Competitors paying full OpenAI/Deepgram/ElevenLabs rates at the same scale will be priced out of the market.
🇦🇺
AU-First Regulatory Edge
ACMA compliance, AU data sovereignty (Sydney AWS region), ABN integration, GST-aware billing. US and European competitors cannot ship to AU market without 12+ months of localisation. TalkByte is already here and compliant.
🔄
Network Effects (Franchise)
When a franchise chain (e.g., 50-location pizza chain) adopts TalkByte, their entire network standardises. One enterprise deal adds 50 restaurants instantly. Franchise management features (centralised menu updates, reporting) create lock-in that SaaS competitors can't easily replicate.
